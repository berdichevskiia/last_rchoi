1. Исследование

Краткий анализ конкурентов и целевой аудитории (ЦА).

  • Цель сервиса: образовательная демонстрация проектирования UI — пример учебного проекта.
  • Конкуренты / референсы: GitHub Pages-демо, простые SaaS-лендинги, учебные портфолио.
  • Целевая аудитория: студенты, преподаватели, разработчики без глубокого UX-опыта.
  • Ключевые требования от ЦА: понятная навигация, простые сценарии, четкая обратная связь на действия.

Выводы исследования: упор на простоту, доступность, мобильную адаптацию и демонстрационную содержательность.

2. Пользовательские сценарии (подробно)

Сценарий A — "Ознакомление с проектом"

  1. Пользователь открывает сайт (index.html).
  2. Видит заголовок, краткое описание и навигацию.
  3. Кликает "Исследование" — переходит к разделу исследования, читает выводы.
  4. Возвращается в навигацию, переходит к "Вайрфреймы" для просмотра набросков.
  5. При необходимости скачивает ZIP с кодом через страницу "Реализация".

Ожидаемое поведение: навигация прокручивает страницу, контент читаем на мобильных и десктопах.

Сценарий B — "Тестовое задание / проверка элементов"

  1. Пользователь открывает раздел "Реализация".
  2. Нажимает кнопку "Открыть демо". Откроется тестовая страница с интерактивными элементами (формы/модалки).
  3. Заполняет форму обратной связи и нажимает "Отправить".
  4. Сайт показывает уведомление об успешной отправке (локально — эмуляция через JavaScript).

Ожидаемое поведение: видно явную обратную связь (уведомление), поля валидируются, кнопка недоступна при пустых полях.

Сценарий C — "Проверка аналитики (демо) и поведение пользователя"

  1. Администратор вставляет код счётчика (Яндекс.Метрика) в <head> (в проекте — пример).
  2. Пользователь переходит между разделами и кликает ссылки — счётчик фиксирует события (в реальном развёртывании).
  3. Администратор через интерфейс Яндекс.Метрики изучает карты кликов и вебвизор.

Примечание: в ZIP — пример вставки кода метрики и комментарий о необходимости заменить ID на реальный.

Сценарий D — "Получение отчёта"

  1. Студент формирует отчёт: копирует тексты из разделов "Исследование", "Структура", "Вайрфреймы", "Стиль".
  2. Генерирует PDF локально (например, через печать браузера в PDF) и прилагает к защите.

Ожидаемое поведение: все необходимые материалы доступны на одной странице и легко экспортируются в PDF.

3. Структура сервиса

Иерархия страниц и переходы (упрощённо):

Home

 ├─ Структура (section)
 ├─ Вайрфреймы (section)

Переходы реализованы как якорные ссылки на единую страницу (SPA-like, без фреймворков).

5. Стиль (стайлгайд)

  • Шрифты: Inter или system-ui (альтернатива для оффлайн).
  • Цвета: акцент — #2b6cb0 (синий), фон — #f7fafc, текст — #222.
  • Кнопки: крупные, с закруглением 8–12px, явная тень.
  • Иконки: минималистичные, одноцветные.
  • Сетка: 12 колонок, адаптивная.

В проекте стили демонстрируют выбранную палитру — они находятся в styles.css.

6–7. Реализация и запуск (код в ZIP)

Этот пакет содержит статический сайт. Для запуска:

  1. Скачать ZIP и распаковать.
  2. Открыть index.html в браузере или запустить простой HTTP-сервер (рекомендуется):
python -m http.server 8000
# затем открыть http://localhost:8000
